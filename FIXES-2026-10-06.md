# Morning Loop: Cross-Platform & Robustness Fixes (2026-10-06)

This release fixes 9 critical issues discovered in user testing on Linux and Windows, plus adds polish for reliability.

## What Was Fixed

### Critical Issues (Tier 1: Ship-Ready)

**1. Linux network gate failed (Issue #1)**
- Problem: `nc -z -G` and `dscacheutil` are macOS-only; Linux runners hung indefinitely
- Fix: Portable Python socket probe with `nc` fallback; no platform branching
- Impact: Linux scheduled runners now work end-to-end
- Files: All three runner templates

**2. Unguarded `caffeinate` calls (Issue #2)**
- Problem: Linux/Windows croaked with "command not found: caffeinate"
- Fix: Added `HAVE_CAFF` guard (like opencode/codex already had)
- Impact: Runners degrade gracefully on systems without caffeinate
- Files: `run-prep.template.sh` (others already had it)

**3. macOS-specific error messages on Linux (Issues #E, #9)**
- Problem: "launchd.log", "The Mac slept mid-run", "DarkWake" on Linux dashboards were confusing
- Fix: Runtime `uname` checks; messages adapt by platform
- Impact: Users see actionable guidance for their OS
- Files: All three runner templates; error message paths now context-aware

**4. Windows launcher trusts PATH without testing (Issue #4)**
- Problem: `where py` finds Store alias stubs that open the Microsoft Store instead of running Python
- Fix: Actually run `py -3 -c "import sys"` to verify it works; show Store alias fix
- Impact: New users on Windows get clear guidance instead of cryptic failure
- Files: `Start here - Windows.bat`

**5. macOS launcher lacks Gatekeeper instructions for Sequoia (Issue #8)**
- Problem: Right-click > Open no longer works on macOS 15+; users hit a hard stop
- Fix: Documented the Sequoia path (Settings > Privacy & Security > Open Anyway)
- Impact: Workshop participants on current macOS unblocked
- Files: `Start here - Mac.command`, `docs/GETTING-STARTED.md`

**6. `python3` hardcoded in 35+ places (Issue #5)**
- Problem: Windows installer doesn't create `python3.exe`; users hit Store alias; other clients may use different invocations
- Fix: `setup.py` probes for working interpreter (`py -3`, `python3`, `python`); stores in `config.yml`; quick fallback note in docs
- Impact: Commands use what actually works; one-line fix in docs if Store alias isn't disabled
- Files: `scripts/setup.py`, `templates/config.template.yml`, `docs/GETTING-STARTED.md`

**7. Missing permissions for unattended run (Issue #7)**
- Problem: Clean account, no pre-approved tools; brief might land partial or empty without clear error
- Fix: Claude runners pass `--allowedTools` with one `Bash(<owner.python> morning/engine/<script>.py *)` rule per engine script. No MCP wildcard: Claude Code ignores a bare `mcp__*`, and `mcp__<server>` would pre-approve write tools in a run that reads untrusted text
- Impact: First unattended run on a clean account doesn't stall on engine calls; connector reads are not pre-approved, so the brief is thinner rather than stuck
- Files: `run-prep.template.sh`, `run-prep.template.ps1` (opencode/codex have their own auth models; documented)

**8. Default folder `~/morning` creates `~/morning/morning` (Issue #9)**
- Problem: Confusing nesting on first-time user
- Fix: Changed default to `~/morning-brief`
- Impact: Clearer folder structure for newcomers
- Files: `scripts/quickstart.py`, docs

**9. Tests need zsh and hit real network (Issue #3)**
- Problem: Linux without zsh failed; tests burned credits probing api.anthropic.com
- Fix: Skip zsh checks with a message when not installed; use `MORNING_SKIP_NET_GATE=1` for self-contained tests
- Impact: Tests run offline and on any shell; CI-friendly
- Files: `tests/run.py`

### Polish & Future-Proofing (Tiers 2-3)

**Permissions strategy (Tier 2)**
- Claude runners pre-approve the engine scripts only, never MCP tools
- OpenCode/Codex guidance documented (they use different auth)

**Interpreter detection (Tier 2)**
- Probes for Python 3.9+ at install time; stores working command in config
- Fallback guidance in docs for if Store alias needs disabling

**Symlink health check (Tier 3)**
- Doctor now detects broken symlinks (engine/package links pointing to deleted targets)
- Suggests `--refresh` to repair

**Linux scheduling options (Tier 3)**
- Added comprehensive systemd timer guide as alternative to cron
- Service files with proper environment, logging, and boot/15-min cadence
- Clear enable/disable commands
